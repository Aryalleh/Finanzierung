# 💶 Finanzierung — مدیریت حقوق ماهانه

یک **PWA** (وب‌اپلیکیشن نصب‌شدنی) روی **Cloudflare Workers** برای مدیریت مالی ماهانه به روش «پاکت‌بندی» (Envelope Budgeting).

هر بخش از بودجه یک **پاکت** جداگانه است و برای هر پاکت این‌ها را می‌بینید:

- **ورودی این ماه** — چقدر پول وارد این پاکت شده
- **خروجی این ماه** — چقدر از این پاکت خرج شده
- **موجودی فعلی** — مانده‌ی واقعی پاکت (مجموع ورودی‌ها منهای خروجی‌ها در همه‌ی ماه‌ها)

## پاکت‌های پیش‌فرض (درصد پیشنهادی)

| بخش | درصد پیشنهادی |
| --- | --- |
| 🏠 اجاره و هزینه‌های ثابت | ۳۵–۴۵٪ |
| 🛒 غذا و خرید روزمره | ۱۰–۱۵٪ |
| 🚆 حمل‌ونقل | ۵–۱۰٪ |
| 📱 قبض و اشتراک‌ها | ۵٪ |
| 🎉 تفریح و خرید شخصی | ۱۰٪ |
| 💰 پس‌انداز اضطراری | ۱۰–۱۵٪ |
| 📈 سرمایه‌گذاری / پس‌انداز هدفمند | ۵–۱۰٪ |

پاکت‌ها قابل ویرایش، اضافه‌شدن و حذف‌اند.

## امکانات

- 🔐 **چندکاربره با ورود امن**: ثبت‌نام/ورود با ایمیل و رمز؛ داده‌ی هر کاربر کاملاً جدا و خصوصی است.
- 💸 **تقسیم حقوق**: مبلغ کل حقوق را وارد کنید تا به‌صورت خودکار بر اساس درصد هر پاکت تقسیم و ثبت شود (درصدها قابل تنظیم‌اند).
- ➕➖ ثبت سریع ورودی/خروجی برای هر پاکت.
- 📅 فیلتر بر اساس ماه.
- 💱 انتخاب واحد پول (یورو، دلار، لیر، ریال، تومان).
- 📱 نصب‌شدنی روی موبایل و دسکتاپ + کار در حالت آفلاین (پوسته‌ی برنامه کش می‌شود).
- 🌗 پشتیبانی از حالت تیره و راست‌به‌چپ (RTL).

## امکانات تازه

- 🌍 **حساب مجزا برای هر ارز** — هر پاکت به یک ارز تعلق دارد (تومان، ریال، یورو، دلار، لیر) و از بالای صفحه بین حساب‌های ارزی جابه‌جا می‌شوید؛ موجودی/ورودی/خروجی هر ارز کاملاً جداست.
- 👥 **پاکت مشترک** — مالک می‌تواند کاربر دیگری را (با ایمیل یا `@یوزرنیم` تلگرام) به پاکت اضافه کند؛ موجودی مشترک است و تراکنش هر عضو در مانده‌ی پاکت لحاظ می‌شود.
- 🤝 **قرض بین کاربران** — دفتر قرض: «قرض دادم / قرض گرفتم»، تأیید یا رد طرف مقابل، ثبت بازپرداخت و تسویه؛ خلاصه‌ی طلب و بدهی به تفکیک ارز.
- ✈️ **ورود با تلگرام** — از **مینی‌اپ تلگرام** (ورود خودکار و امن) و در مرورگر با **تأیید/رد دکمه‌ای در تلگرام** (بدون کد).
- 🌗 **حالت تیره/روشن/سیستم** و **پالت رنگ چندگانه** (سبزآبی، بنفش، آبی زمستانی) — از منوی پروفایل.
- 🪙 **مدیریت ارز**: هر کاربر هر ارزی را که بخواهد می‌سازد و می‌تواند حساب ارزی را حذف کند.
- 🖼️ **عکس پروفایل** از تلگرام همگام می‌شود.

## 📊 نمره‌ی مدیریت مالی و رتبه‌بندی

یک **نمره‌ی ۰ تا ۱۰۰** ماهانه که رفتار مالی را **نسبت به درآمد، بودجه و عادت خودِ کاربر** می‌سنجد (نه یک عدد ثابت). اجزا:

| بخش | سقف |
| --- | --- |
| کنترل بودجه‌ی پاکت‌ها (انحراف از بودجه، وزن‌دار) | ۳۵ |
| پس‌انداز و سرمایه‌گذاری (نرخ + بازده کاهشی) | ۳۰ |
| نقدینگی و پوشش هزینه‌های ضروری | ۱۵ |
| ثبات نسبت به ماه قبل (تعدیل‌شده با رشد درآمد) | ۱۰ |
| کنترل ولخرجی (اختیاری نسبت به درآمد/هدف) | ۱۰ |
| پاداش پس‌انداز بهتر از میانگین شخصی | تا +۵ |

- **قرض دادن مثبت است** (مدیریت خوب نقدینگی) و **قرض گرفتن منفی** (به سقف نمره ۶۹ محدود می‌شود).
- هر پاکت یک **نوع** دارد (ضروری/اختیاری/پس‌انداز/سرمایه‌گذاری) که در مودال پاکت قابل تغییر است و مبنای نمره‌دهی است.
- **Momentum**: روند نمره در ۳ ماه اخیر.
- **رتبه‌بندی بین کاربران، به‌تفکیک ارز و ماهانه** — در تب «نمره».
- توصیه‌های خودکار (مثلاً «۴۱٪ بیشتر از بودجه‌ی تفریح خرج کردی»).

> نکته‌ی حریم خصوصی: رتبه‌بندی نام و عکس و نمره‌ی کاربرانِ همان ارز را نشان می‌دهد. برای تولید عمومی بهتر است بعداً گزینه‌ی «شرکت در رتبه‌بندی» (opt-in) اضافه شود.

## احراز هویت و امنیت

- رمزهای عبور با **PBKDF2 (SHA-256، ۱۰۰٬۰۰۰ تکرار، salt تصادفی)** هش می‌شوند؛ رمز خام هرگز ذخیره نمی‌شود.
- نشست‌ها با توکن تصادفی در جدول `sessions` نگه‌داری می‌شوند و کوکی آن‌ها `HttpOnly`, `SameSite=Lax` و روی HTTPS همراه `Secure` است. اعتبار پیش‌فرض: ۳۰ روز.
- تمام مسیرهای داده به‌جز `/api/auth/*` و `/api/health` نیازمند نشست معتبرند و دسترسی بر پایه‌ی **عضویت در پاکت** و مالکیت کنترل می‌شود.

### راه‌اندازی ورود با تلگرام

۱) با [@BotFather](https://t.me/BotFather) یک ربات بسازید و **توکن** آن را بگیرید.
۲) توکن را به‌صورت Secret به Worker بدهید: `npx wrangler secret put TELEGRAM_BOT_TOKEN`
۳) در BotFather یک **Mini App / Web App** بسازید و URL اپ منتشرشده را ثبت کنید؛ کاربر با باز کردن مینی‌اپ داخل تلگرام به‌صورت خودکار و امن وارد می‌شود (اعتبارسنجی `initData` با HMAC).
۴) **ورود در مرورگر با Telegram Login Widget (رسمی):** دکمه‌ی «Log in with Telegram» نمایش داده می‌شود؛ کاربر در تلگرام تأیید می‌کند و مستقیم وارد می‌شود (بدون کد و بدون وب‌هوک). برای اینکه ویجت ظاهر شود باید **دامنه‌ی سایت را به ربات معرفی کنید**:

> در @BotFather → دستور `/setdomain` → ربات را انتخاب کنید → آدرس اپ را بدهید (مثلاً `finanzierung.<اکانت>.workers.dev`).

بدون تنظیم دامنه، دکمه‌ی تلگرام در مرورگر ظاهر نمی‌شود (خطای شایع «کار نکردن ورود تلگرام»). اپ اگر `TELEGRAM_BOT_TOKEN` تنظیم نشده باشد، خودش پیام «ورود تلگرام پیکربندی نشده» را نشان می‌دهد.

> نکته: مسیر قدیمی تأیید/رد رباتی و وب‌هوک هنوز در بک‌اند وجود دارد ولی روش پیش‌فرض مرورگر حالا **Login Widget** است که مطمئن‌تر است.

> پیشنهاد تولید: نرخ‌محدودسازی ورود، تأیید ایمیل و بازیابی رمز را می‌توان بعداً افزود.

## معماری

```
├── src/worker.js            ← Cloudflare Worker: API + سرو فایل‌های ثابت
├── src/input.css            ← ورودی Tailwind (کامپایل می‌شود به public/styles.css)
├── tailwind.config.js       ← پیکربندی Tailwind (رنگ‌های برند، فونت)
├── public/                  ← رابط کاربری PWA (استاتیک)
│   ├── index.html
│   ├── app.js
│   ├── styles.css           ← خروجی کامپایل‌شده‌ی Tailwind (با npm run build:css)
│   ├── manifest.webmanifest
│   ├── sw.js                ← Service Worker (آفلاین)
│   └── icons/
├── migrations/0001_init.sql ← طرح پایگاه‌داده (users, sessions, pockets, transactions)
├── docs/DESIGN_HANDOFF.md   ← سند تحویل به طراح (توکن‌ها، صفحات، کامپوننت‌ها)
└── wrangler.toml            ← پیکربندی Cloudflare
```

داده‌ها در **Cloudflare D1** (پایگاه‌داده SQLite) ذخیره می‌شوند. Worker در اولین درخواست، جدول‌ها را در صورت نبود می‌سازد. پاکت‌های پیش‌فرض هنگام **ثبت‌نام هر کاربر** برای همان کاربر ساخته می‌شوند.

رابط کاربری با **Tailwind CSS** ساخته شده و به یک فایل استاتیک کامپایل می‌شود (بدون CDN زمان‌اجرا). آیکن‌ها از Font Awesome و فونت از Vazirmatn (Google Fonts) بارگذاری می‌شوند. اسکریپت‌های `dev` و `deploy` قبل از اجرا، CSS را به‌صورت خودکار می‌سازند؛ برای ساخت دستی: `npm run build:css` (یا `npm run watch:css` هنگام توسعه).

## راه‌اندازی و انتشار

پیش‌نیاز: حساب Cloudflare و [Node.js](https://nodejs.org).

```bash
# ۱) نصب وابستگی‌ها
npm install

# ۲) ورود به حساب Cloudflare
npx wrangler login

# ۳) ساخت پایگاه‌داده D1
npm run db:create
#    خروجی یک database_id می‌دهد؛ آن را در wrangler.toml جایگزین REPLACE_WITH_YOUR_DATABASE_ID کنید.

# ۴) ساخت جدول‌ها و درج پاکت‌های پیش‌فرض
npm run db:init

# ۵) انتشار
npm run deploy
```

پس از انتشار، آدرس `*.workers.dev` به شما داده می‌شود؛ آن را در مرورگر باز کنید و از منوی مرورگر گزینه‌ی «نصب برنامه / Add to Home Screen» را بزنید.

## اجرای محلی (برای توسعه)

```bash
npm install
npm run db:init:local   # ساخت جدول‌ها در پایگاه‌داده‌ی محلی
npm run dev             # اجرای محلی روی http://localhost:8787
```

## API

| متد | مسیر | توضیح |
| --- | --- | --- |
| `POST` | `/api/auth/register` | ثبت‌نام (`email`, `password`) → کوکی نشست |
| `POST` | `/api/auth/login` | ورود → کوکی نشست |
| `POST` | `/api/auth/logout` | خروج |
| `GET` | `/api/auth/me` | کاربر جاری |
| `GET` | `/api/pockets?month=YYYY-MM` | فهرست پاکت‌ها با ورودی/خروجی ماه و موجودی کل |
| `POST` | `/api/pockets` | ساخت پاکت |
| `PUT` | `/api/pockets/:id` | ویرایش پاکت |
| `DELETE` | `/api/pockets/:id` | حذف پاکت |
| `GET` | `/api/summary?month=YYYY-MM` | جمع کل ورودی/خروجی/موجودی |
| `GET` | `/api/transactions?month=&pocket_id=&limit=` | فهرست تراکنش‌ها |
| `POST` | `/api/transactions` | ثبت تراکنش (`type`: `income` یا `expense`) |
| `DELETE` | `/api/transactions/:id` | حذف تراکنش |
| `POST` | `/api/distribute` | تقسیم حقوق بین پاکت‌ها |

نمونه‌ی تقسیم حقوق:

```json
POST /api/distribute
{
  "amount": 2500,
  "occurred_on": "2026-09-01",
  "allocations": [
    { "pocket_id": 1, "percent": 40 },
    { "pocket_id": 2, "percent": 12 }
  ]
}
```

اگر `allocations` ارسال نشود، از نقطه‌ی میانی بازه‌ی درصد هر پاکت استفاده و نسبت به مجموع نرمال‌سازی می‌شود.
